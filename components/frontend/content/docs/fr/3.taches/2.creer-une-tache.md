---
title: Créer une tâche
---

::lead
Apprenez à définir des tâches individuelles ou récurrentes pour surveiller la bonne éxécution de vos processus critiques.
::

La première étape pour surveiller un processus est de définir une tâche. Une fois la tâche définie, vous pourrez [éxécuter la tâche](/docs/taches/executer-une-tache).

### Création de tâche via le Dashboard

Vous pouvez créer une tâche depuis le formulaire du dashboard dédié à cet effet. Utilisez le bouton <button class="btn btn-primary btn-sm">Nouvelle tâche</button> pour accéder au formulaire.

Voilà une description des principales options disponibles.

#### Options générales

- **Nom de la tâche**: Utilisé pour identifier la tâche dans le dashboard. Le nom est obligatoire mais il n'a pas besoin d'être unique. Utilisez un nom explicite tel que "Backup hebdomadaire de la base de données".
- **Description**: Une description optionnelle de la tâche, pour mieux vous y retrouver. Mettez-y ce que vous voulez.
- **Notifications**: Permet de configurer les notifications qui seront envoyées en cas d'échec, de retard, ou d'absence de la tâche. Par exemple, si une tâche est particulièrement critique, vous pouvez choisir de recevoir
une notification par SMS.
- **Métadonnées**: Les métadonnées sont des données arbitraires, organisées en paires d'une clé et d'une valeur, que vous pouvez associer à votre tâche. Elles vous permettent de filtrer les tâches
et les incidents associés. Par exemple, si vous avez plusieurs tâches liées à même environnement, vous pourriez donner à toute ces tâches la paire de métadonnées `environnement: production`. Plus tard,
vous pourrez ainsi filtrer les tâches et les incidents dans le dashboard selon leur appartenance à l'environnement.

#### Options pour les tâches planifiées

Les tâches peuvent être planifiées, c'est à dire qu'on s'attend à ce qu'elles s'éxécutent à intervalle régulier. Si une tâche planifiée ne démarre pas au moment prévu, un incident sera créé et une notification pourra
être envoyée aux membres de votre organisation (voir les paramètres de notifications).

- **Planification**: l'intervalle d'éxécution de la tâche, au format [Cron](https://fr.wikipedia.org/wiki/Cron). Lorsque vous editez la planification au format Cron, une petit texte vous explique la planification dans un format plus facilement compréhensible. 
- **Fuseau horaire**: Fuseau horaire utilisé pour calculer l'heure d'éxécution prévue de la tâche. Par défaut, il s'agit du fuseau UTC.
- **Fenêtre de début**: Fenêtre de temps durant laquelle la tâche est attendue. Si la tâche ne démarre pas dans cette fenêtre, elle sera considérée comme en retard et un incident sera créé. Par exemple, si une tâche
est censée démarrer à 9h00, et que la fenêtre de début est de 120 secondes, la tâche peut démarrer entre 9h00 et 9h02. Elle sera considérée comme en retard au delà de 9h02.
- **Fenêtre de fin de retard**: Fenêtre de temps, commençant après la fenêtre de début, durant laquelle une tâche en retard peut encore s'éxécuter. Si la tâche en retard ne démarre pas dans cette fenêtre, elle sera considérée comme échouée. Par exemple, si une tâche est censée démarrer à 9h00, et que les fenêtres de début et de fin de retard sont respectivement de 2 et 3 minutes, la tâche sera:
  - à l'heure si elle démarre entre 9h00 et 9h02
  - en retard si elle démarre entre 9h02 et 9h05
  - absente si ne démarre toujours pas après 9h05

#### Options avancées

- **id de la tâche**: un identifiant unique pour la tâche. Utilisé pour lancer la tâche à l'aide de l'utilitaire ou via l'API. Il doit être unique et ne contenir que des caractères alphanumériques et des tirets. Par défaut, il est généré à partir du nom de la tâche.
- **Timeout pour le battement de coeur**: une fois une tâche démarrée, elle est attendue à envoyer un signal périodique à DutyDuck pour confirmer qu'elle est toujours en cours d'exécution. Si nous ne recevons pas de signal de la tâche dans cette fenêtre, elle sera considérée comme échouée. Si vous utilisez l'utilitaire DutyDuck pour lancer la tâche, vous n'avez rien à faire de plus pour envoyer ce signal.

### Création de tâche via l'outil en ligne de commande

[Installation de l'outil en ligne de commande](/docs/introduction/outil-en-ligne-de-commande)

La commande `dutyduck tasks run ...`, qui est utilisée pour lancer une tâche, peut aussi être utilisée pour créér une nouvelle tâche à la volée si celle ci n'existe pas déjà, en ajoutant l'option `--create`.

Ainsi, si vous essayez de lancer la tâche `db-backup` et que celle-ci n'existe pas, le comportement par défaut de l'outil est de rejeter votre requête:

```shell
$ dutyduck tasks run --task-id db-backup sleep 10`
Error: Failed to send start task request

Caused by:
    API responded with an invalid status code: 404 Not Found and body: Task not found
```

Mais, dès lors que vous utilisez l'option `--create`, la tâche sera créé avant d'être lancée, et tout fonctionnera correctement.

```shell
dutyduck tasks run --create --task-id db-backup sleep 10
```

D'autres options sont disponibles afin de personnaliser la tâche ainsi créée:

- `--name`
- `--description`
- `--start-window-seconds`
- ...

N'oubliez pas que vous pouvez utiliser `--help` à tout moment pour en apprendre plus sur le fonctionnement de l'outil en ligne de commande.

```shell
$ dutyduck tasks run tasks run --help
Run a process locally, wrapped in a task run. The status of the process will be reported back to the platform

Usage: dutyduck tasks run [OPTIONS] --task-id <TASK_ID> <COMMAND> [ARGS]...

Arguments:
  <COMMAND>  The command to run
  [ARGS]...  The arguments to pass to the command

Options:
      --task-id <TASK_ID>
          The id of the task to run
      --create
          Create the task if it does not exist
      --abort-previous-running-task
          Whether to abort the previous running task if there is a running task with the same id
      --name <NAME>
          The name of the newly-created task
      --description <DESCRIPTION>
          The description of the newly-created task
      --cron-schedule <CRON_SCHEDULE>
          The cron schedule of the newly-created task
      --start-window-seconds <START_WINDOW_SECONDS>
          The start window of the newly-created task
      --lateness-window-seconds <LATENESS_WINDOW_SECONDS>
          The lateness window of the newly-created task
      --heartbeat-timeout-seconds <HEARTBEAT_TIMEOUT_SECONDS>
          The heartbeat timeout of the newly-created task
```

### Création de tâche via l'API

L'API REST vous permet de programmer tout ce que vous feriez à travers le dashboard. L'endpoint `POST /tasks` vous permet de créer une tâche. Consultez notre documentation pour les développeurs pour savoir
comment appeler notre API.
