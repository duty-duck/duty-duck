---
title: Execute a Task
---

::lead
Learn how to track the execution of a task in DutyDuck.
::

Once a task is created (see [Create a Task](/en/docs/tasks/create-a-task)), you have several options to track its execution. A task can be executed multiple times, and each task can have multiple executions, each with a date and status. Thus, if you have a task *Database Backup*, and you perform it every day, you will have one execution per day and can see which days the task was executed successfully and which days it failed.

The different possible states for a task are explained in detail on the [next page](/en/docs/tasks/task-states).

### Launch a Task Using the Command Line Tool

Using the command line tool to launch a task is the simplest method. The tool handles both launching the command you provide and recording the execution result and logs in DutyDuck. To use the command line tool, you need an authentication token. You can generate one from the DutyDuck web interface in the *My Account* section.

More information about our command line tool is available [on the dedicated page](/en/docs/introduction/command-line-tool).

The command `dutyduck tasks run` allows you to launch any command and record the execution result in DutyDuck. You need to provide the task identifier to launch with the `--task-id` option, then the command to launch. For example:

```shell
dutyduck tasks run --task-id daily-sales-report ./generate-report.sh
```

The command line tool also allows you to create a new task definition if it does not already exist. To do this, you can use the --create option. More information on task creation

The command line tool will automatically pass the task's environment variables to the command you are launching and will automatically capture the command output so you can consult the task logs later.

### Record an Execution Using the API (Advanced Users)

You are not limited to the command line tool to record a task execution. You can also use the DutyDuck REST API to manually record a task execution. This allows you to capture the result of any process, not just commands or scripts. For example, you can integrate our API directly into an application to track the successful execution of a task internal to your application.

You will need to:

1. Use the POST /tasks/:task_id/start endpoint to create a task execution
2. Use the POST /tasks/:task_id/heartbeat endpoint regularly to indicate that the task is still running
3. Use the POST /tasks/:task_id/finish endpoint to indicate that the task is completed, successfully or not

#### Heartbeats
The POST /tasks/:task_id/heartbeat endpoint must be called regularly to indicate that the task is still running. If you do not do this, the task will be marked as failed after a certain time. This time is configurable for the task, but we recommend not increasing it too much.

This mechanism allows DutyDuck to detect that a task is no longer responding, either because the process is blocked, the process crashed without being able to send a task completion message, or the connection to the DutyDuck server was lost while the task was running. This allows you to say: "This task is no longer giving news, something is wrong."

#### Execution Logs
You can send execution logs for a task using the POST /tasks/:task_id/logs endpoint. This allows you to track the task execution in real-time and retrieve the task execution details later in the dashboard.
