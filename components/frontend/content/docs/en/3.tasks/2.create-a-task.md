title: Create a Task

::lead
Learn how to define individual or recurring tasks to monitor the successful execution of your critical processes.
::

The first step to monitor a process is to define a task. Once the task is defined, you can [run the task](/en/docs/tasks/execute-a-task).

### Task Creation via the Dashboard

You can create a task from the dashboard form dedicated to this purpose. Use the <button class="btn btn-primary btn-sm">New Task</button> button to access the form.

Here is a description of the main options available.

#### General Options

- **Task Name**: Used to identify the task in the dashboard. The name is required but does not need to be unique. Use an explicit name such as "Weekly Database Backup".
- **Description**: An optional description of the task for better clarity. Put whatever you want.
- **Notifications**: Allows you to configure notifications that will be sent in case of failure, delay, or absence of the task. For example, if a task is particularly critical, you can choose to receive a notification via SMS.
- **Metadata**: Metadata are arbitrary data, organized in key-value pairs, that you can associate with your task. They allow you to filter tasks and related incidents. For example, if you have multiple tasks related to the same environment, you could give all these tasks the metadata pair `environment: production`. Later, you can filter tasks and incidents in the dashboard based on their environment.

#### Options for Scheduled Tasks

Tasks can be scheduled, meaning they are expected to run at regular intervals. If a scheduled task does not start at the expected time, an incident will be created, and a notification can be sent to members of your organization (see notification settings).

- **Schedule**: The execution interval of the task, in [Cron](https://en.wikipedia.org/wiki/Cron) format. When you edit the schedule in Cron format, a small text explains the schedule in a more easily understandable format.
- **Time Zone**: Time zone used to calculate the expected execution time of the task. By default, it is the UTC time zone.
- **Start Window**: Time window during which the task is expected. If the task does not start within this window, it will be considered late, and an incident will be created. For example, if a task is supposed to start at 9:00 AM and the start window is 120 seconds, the task can start between 9:00 AM and 9:02 AM. It will be considered late after 9:02 AM.
- **Lateness Window**: Time window, starting after the start window, during which a late task can still execute. If the late task does not start within this window, it will be considered failed. For example, if a task is supposed to start at 9:00 AM and the start and lateness windows are 2 and 3 minutes respectively, the task will be:
  - on time if it starts between 9:00 AM and 9:02 AM
  - late if it starts between 9:02 AM and 9:05 AM
  - absent if it still does not start after 9:05 AM

#### Advanced Options

- **Task ID**: A unique identifier for the task. Used to run the task using the utility or via the API. It must be unique and contain only alphanumeric characters and dashes. By default, it is generated from the task name.
- **Heartbeat Timeout**: Once a task has started, it is expected to send a periodic signal to DutyDuck to confirm that it is still running. If we do not receive a signal from the task within this window, it will be considered failed. If you use the DutyDuck utility to run the task, you do not need to do anything extra to send this signal.

### Task Creation via the Command-Line Tool

[Command-Line Tool Installation](/en/docs/intro/cli-tool)

The command `dutyduck tasks run ...`, which is used to run a task, can also be used to create a new task on the fly if it does not already exist, by adding the `--create` option.

Thus, if you try to run the task `db-backup` and it does not exist, the default behavior of the tool is to reject your request:

```shell
$ dutyduck tasks run --task-id db-backup sleep 10
Error: Failed to send start task request

Caused by:
    API responded with an invalid status code: 404 Not Found and body: Task not found
```

But, as soon as you use the --create option, the task will be created before being run, and everything will work correctly.

```shell
dutyduck tasks run --create --task-id db-backup sleep 10
```

Other options are available to customize the task created this way:

- `--name`
- `--description`
- `--start-window-seconds`
- ...

Don't forget that you can use --help at any time to learn more about how the command-line tool works.

```shell
$ dutyduck tasks run tasks run --help
Run a process locally, wrapped in a task run. The status of the process will be reported back to the platform

Usage: dutyduck tasks run [OPTIONS] --task-id <TASK_ID> <COMMAND> [ARGS]...

Arguments:
  <COMMAND>  The command to run
  [ARGS]...  The arguments to pass to the command

Options:
      --task-id <TASK_ID>
          The id of the task to run
      --create
          Create the task if it does not exist
      --abort-previous-running-task
          Whether to abort the previous running task if there is a running task with the same id
      --name <NAME>
          The name of the newly-created task
      --description <DESCRIPTION>
          The description of the newly-created task
      --cron-schedule <CRON_SCHEDULE>
          The cron schedule of the newly-created task
      --start-window-seconds <START_WINDOW_SECONDS>
          The start window of the newly-created task
      --lateness-window-seconds <LATENESS_WINDOW_SECONDS>
          The lateness window of the newly-created task
      --heartbeat-timeout-seconds <HEARTBEAT_TIMEOUT_SECONDS>
          The heartbeat timeout of the newly-created task
```

### Task Creation via the API

The REST API allows you to program everything you would do through the dashboard. The POST /tasks endpoint allows you to create a task. Consult our developer documentation to learn how to call our API.

- [How to Access the API](/en/docs/developers)
